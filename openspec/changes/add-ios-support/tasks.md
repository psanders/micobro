- [x] 6.2 Add the config plugin entry `["@react-native-google-signin/google-signin", { iosUrlScheme: "com.googleusercontent.apps.<reversed-ios-client-id>" }]` to `app.config.ts`. The plugin validates the `com.googleusercontent.apps.` prefix and appends the Info.plist scheme itself — no native code, no manual CocoaPods step. Derived the reversed scheme from `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` (one env var, not two) and the plugin entry is omitted entirely while the id is unset, since the plugin throws on an empty `iosUrlScheme` rather than tolerating one — verified with `expo config --json` both empty and with a fake client id.
- [x] 6.3 Add a `getIosClientId()` helper in `lib/sync/googleAuth.ts` mirroring `getWebClientId()`, and pass `iosClientId` in `GoogleSignin.configure()`. Leave `webClientId`, the `drive.file` scope, and every other function untouched — `hasPlayServices()` already no-ops on iOS. Guarded so Android never calls `getIosClientId()` — an unset iOS client id can't break Android.
  - **Real crash found and fixed by actually running the app on the simulator, not by review.** `isSignedInToGoogle()` — called passively on every app launch via `SyncProvider.refreshStatus()`, not just when a lender taps "Continuar con Google" — called `configureGoogleSignin()` unconditionally, which threw whenever a required client id was missing. With `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` still empty (task 0.2 not done yet), this crashed the app on iOS on every launch, caught live via a red-screen error overlay on the running simulator build. **This bug is not iOS-specific** — the same unconditional-throw path exists for `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` on Android too, just never triggered there because that var has always been set locally. Fixed by adding `isGoogleAuthConfigured()` (no throw, just a boolean) and having `isSignedInToGoogle()` / `getValidAccessToken()` short-circuit to "not signed in" / `null` when config is incomplete, instead of calling into `GoogleSignin` at all. `signInWithGoogle()` still throws if invoked without config — acceptable, since the UI already disables that path (spec `google-connect`).
